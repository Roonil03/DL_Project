# User run review — 11 November 2026

Run `full-validation` is a historical backtest from the user's local CUDA
container. The run manifest records source commit
`6e1fd1b754ee957d593a22bc23911d5a9ec60b9a`, PyTorch `2.4.1+cu124`,
Python `3.11.11`, CUDA `12.4`, and an NVIDIA GeForce RTX 3060 Laptop GPU.
The exact daily and monthly Kaggle inputs are identified by SHA-256 in the
local `metadata/run_manifest.json`; raw data is not distributed in Git.

Four architectures (DLinear, LSTM, genuine Mamba, PatchTST), five seeds
(42, 52, 62, 72, 82), and fold 0 have metric tables and unit-complete events.
The optional `ahat_fin` architecture was not requested. No MoE experiment
was run. The selected assets were NIFTY50, SP500, USDINR, GOLD and BRENT.
The forecast target is the next recorded return after a 20-observation
lookback. The recorded cost sweep was 0, 1, 5, 10 and 20 basis points.
All 20 learned-model return files share 125 portfolio decision dates,
2013-02-18 through 2013-08-09. The 625 predictive observations in metric
tables count five assets per date, not 625 independent days.

At 5 basis points, the generated report records mean Sharpe (seed standard
deviation): DLinear -0.4568 (0.9983), LSTM -0.6172 (1.1431), Mamba 0.5511
(0.6568), and PatchTST 0.3800 (0.7999). These are observations from one
fold, not evidence of robust superiority. Predictive MSE and directional
accuracy are listed in `Final_Metrics.md`. Per-seed/fold CSVs, regime counts,
predictions and cost sweeps remain in the local run tree. Recorded unit
durations have median 17 seconds and P95 25 seconds; these include notebook
setup and do not estimate a new GPU or data configuration.

## Evidence limits and inconsistencies

- The resolved data config names 2018 validation and 2020 test dates, but
  fold 0 metadata records training 2010-03-26 to 2012-07-19, validation
  2012-07-20 to 2013-02-15, and test decisions 2013-02-18 to 2013-08-09.
  The experiment used index-based walk-forward boundaries. The configured
  calendar split was not the actual evaluation split. Interpret scores only
  for the recorded fold and matched decision dates.
- `telemetry/run_state.json` says `complete` and all 20 units have completion
  events. `telemetry/failures.json` still lists failed units from earlier
  attempts. This file was not cleared on successful resume; inspect event
  history to distinguish prior failures from final status.
- The local transfer ZIP omits checkpoints, but its included
  `bundle_manifest.json` was generated before filtering and lists checkpoint
  files. Its completeness claims therefore do not match the ZIP. The local
  output directory is the fuller evidence record. Do not use the ZIP alone
  as an independently verified replay package.
- A local SHA-256 replay of 468 manifest entries found two changed files:
  `logs/events.jsonl` and `logs/run.log`. The runner appends its final
  completion messages after writing the manifest. All other listed local
  files matched at review time.
- The optional attention model has no run results or ablations. It uses
  dual temporal/feature attention and gated fusion, but does not implement
  the cited AHAT-Fin paper's complete volatility scaling or multiscale state
  design. No AMoE implementation or expert-collapse result is present.
- This is a historical backtest. Live performance, broader regime
  generalization and one-fold confidence are unverified. Raw data must be
  obtained separately under its license to rerun the repository.

The report figures under the ignored local
`outputs/full-validation/figures/summary/` are generated from run outputs;
none are copied into Git because the archive and data-integrity discrepancy
needs resolution first.
